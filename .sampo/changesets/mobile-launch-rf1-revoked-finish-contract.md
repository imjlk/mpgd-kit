`FinishTransactionInput` (and the `commerce.v2.finishTransaction` bridge payload) is now a union: `GrantedFinishTransactionInput`, the finish after a ledger grant (unchanged; `revoked` absent or false), or `RevokedFinishTransactionInput` (`revoked: true`, `isConsumable: true`, `ledgerEntryId` optional): finish a consumable the store revoked (refunded) while it was still unfinished, without any grant. The ledger entry names the reversed grant when there was one and is absent when nothing was granted. `CommerceProvider.acceptsRevokedFinish` gates it the way `acceptsFinishRetry` gates `retry`. A provider that reads `ledgerEntryId` narrows on `revoked` first. `createStoreCommerceProvider` declares the flag, forwards the revoked finish, and keeps the SDK's revoked consumables of the catalog in `getAvailablePurchases` (state `revoked`) only for a `StoreSdk` that declares `acceptsRevokedFinish`; `StoreSdkFinishTransactionInput` is the same union. A revoked finish sent to any other SDK answers `{ finished: false }` without calling it. The conformance vector format gains `profile.revokedFinish` and `finishCalls[].revoked` (with `ledgerEntryId` optional and an `unfinished` result), and the reference reconciler and fixture store implement the revoked finish. A bridge host on an earlier `@mpgd/platform` rejects the new shape, so update the host and the webview together.
