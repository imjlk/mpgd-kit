`createStoreCommerceProvider` takes an optional `purchaseGate`, a sales switch for new purchases separate from the account binding. It is asked once per `requestPurchase` with `{ store, logicalId, storeSku, kind, source }`, after the product, availability, and kind checks and before `accountBinding`, and never by recovery, restore, finishing, events, `fetchProducts`, or `getAvailablePurchases`, so paid purchases keep reconciling while new sales are refused. A refusal never opens the store UI and answers `{ outcome: 'failed' }` with `ITEM_UNAVAILABLE` and `storeCode` `PURCHASES_PAUSED` (or the gate's own code); a gate that throws or answers something malformed refuses with `PURCHASE_GATE_FAILED`, retryable (a thrown `CommerceError` keeps its code unless it claims a launched or cancelled sheet: `OUTCOME_UNKNOWN`, `ALREADY_OWNED`, and `USER_CANCELLED` become `PURCHASE_GATE_FAILED`). A failed or missing account binding is now also answered as a `failed` result instead of a thrown error, so its `storeCode` survives the bridge (a thrown error crosses it without one); a lookup that throws anything but a `CommerceError` is `ACCOUNT_BINDING_REQUIRED` with `ACCOUNT_BINDING_LOOKUP_FAILED`, retryable, and launched or cancelled codes become that too. New exports: `StorePurchaseGate`, `StorePurchaseGateRequest`, `StorePurchaseGateDecision`, `purchasesPausedStoreCode`, `purchaseGateFailedStoreCode`, `accountBindingLookupFailedStoreCode`. A refused attempt is journaled as terminal `failed` by the reconciler, so a retry uses a new idempotency key (trusted `not-started` facts across the bridge are left to a later change). Capabilities are unchanged: a shop hides buy buttons from the same server flag it hands the gate.
