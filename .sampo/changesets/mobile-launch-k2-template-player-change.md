npm/@mpgd/cli: minor (Changed)
---

Generated games fail closed when another player signs in within a run, instead of keeping the first player's game services with a warning. `createStarterGameServices` passes the server session's player to the runtime (`sessionPlayerId`), so from the moment the session names another player nothing is verified, restored, or finished for the boot player with the new player's credentials and no purchase opens a store sheet (purchases answer `failed` with the retryable diagnostic `GAME_SERVICES_PLAYER_CHANGED`). The new `onPlayerChanging` hears the change at once (`main.ts` stops play with an execution block and shows "Switching player..."), the services are disposed (an open store sheet first records its answer), and the new `onPlayerChanged` then restarts the game for the new player (`main.ts` reloads, `restartForAnotherPlayer`). Each services instance pins the store account binding to its player until it is disposed (new `pinStarterCommercePlayer` in `commerceAccountBinding.ts`): while the session names anyone else a purchase binds nothing and is refused before any store sheet, and services for a second player cannot be created while the first player's are open (`StarterCommercePinConflictError`). The runtime also gets the player's own store account binding (new `resolveStarterStoreAccountBindingFor`), so a store purchase bound to another player's account (Google Play lists the previous player's unacknowledged purchases after a restart) is left for that player instead of being verified with this one's session. The session-gated services (`sessionGatedServices.ts`) close the same way on a later sign-in naming another player, gain `dispose()`, and drop recovery and Delete account once closed. Services created for another player than the server session's (for example the native shell's local placeholder) are closed at once, release their pin, and warn (no restart). The reference guest session never changes player, so a game without its own account switching sees no change except the binding comparison.

A game that copied the template's `src/platform` files and adopts this keeps `createStarterGameServices` on the server session's player, wires `onPlayerChanging` and `onPlayerChanged` (or its own restart), and, with its own account binding scheme, replaces `resolveStarterStoreAccountBindingFor` together with the binding functions and the backend resolvers.
