`mpgd deploy run` records a native build's crash symbols in its immutable build record and keeps them next to the artifact in `.mpgd/releases/<release>/`. Android: the R8 `mapping.txt` of a minified release build (`r8Mapping`), which the Google Play submission (`deploy run`, and `deploy submit` for that build) now uploads as the bundle's deobfuscation file without `--mapping-file`; an explicit `--mapping-file` with other bytes is refused, and a build without a mapping is unchanged. iOS, for a shell with `@capacitor-firebase/crashlytics`: the archive's dSYMs (zipped, with their UUIDs), Firebase's `upload-symbols` from the build's Swift Package checkout, and the bundled `GoogleService-Info.plist` (`crashlyticsSymbols`); such an archive is refused without dSYMs, tool or plist. `deploy run` uploads those dSYMs once with `upload-symbols -gsp <plist> -p ios <zip>` after the store submissions and records `uploaded` or `failed` (`symbolUploads` in `deploy status`); a failure is reported with the retry command and never fails the store submission. New `mpgd deploy symbols --game-id <id> --release <release> [--dry-run]` re-runs the upload for an existing build, or prints the command without running it. A release-state file that holds these new fields needs this CLI version or newer.
