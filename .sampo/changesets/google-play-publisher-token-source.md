---
npm/@mpgd/game-services: minor (Added)
---

The Google Play publisher client now has a token source in the kit. `createGooglePlayPublisherAccessTokenSource` and `googlePlayPublisherScope` (from `@mpgd/game-services/google-play-publisher-client`) mint Play Developer API access tokens from a game-owned service-account key that `parseGoogleServiceAccount` reads: pass the source's `get` as `getAccessToken` and its `invalidate` as the client's new `invalidateAccessToken` option, which the client calls with a token Google answered HTTP 401 for, so the next request mints a new one (at most once a minute, since Play also answers 401 for a missing Play Console permission). The source is `createGoogleAccessTokenSource` from the new `@mpgd/game-services/google-access-token` subpath with the Play scope, and that function serves any Google API scope; `createFcmAccessTokenSource` is now the same source with the FCM scope and keeps its API, and `FcmAccessTokenError` now extends the new `GoogleAccessTokenError`. Every source signs through WebCrypto (no new dependency), caches a token until five minutes before it expires, and shares one token request between concurrent callers. Each token request is now bounded by its timeout with its response body, also when an injected `fetch` ignores the signal, and its answer by 16 KiB; an answer that comes after the timeout is cancelled. No caller waits longer than the timeout and a second, even on a request whose Worker request ended before Google answered. A redirect is refused (`TOKEN_REDIRECTED` when the fetch followed it), so is a token that is not a bearer token (`TOKEN_MALFORMED_RESPONSE`), and a `timeoutMs` that is not a positive number now throws when the source, or the FCM provider that makes one, is created. Errors carry a code, never the private key, the signed assertion, or a token. A backend that mints its own Play tokens can switch to the source; FCM needs no change.
