---
npm/@mpgd/game-services: minor (Added)
---

The Google Play publisher client now has a token source in the kit. `createGooglePlayPublisherAccessTokenSource` and `googlePlayPublisherScope` (from `@mpgd/game-services/google-play-publisher-client`) mint Play Developer API access tokens from a game-owned service-account key that `parseGoogleServiceAccount` reads: pass the source's `get` as `getAccessToken` and its `invalidate` as the client's new `invalidateAccessToken` option, which the client calls with a token Google answered HTTP 401 for, so the next request mints a new one. The source is `createGoogleAccessTokenSource` from the new `@mpgd/game-services/google-access-token` subpath with the Play scope, and that function serves any Google API scope; `createFcmAccessTokenSource` is now the same source with the FCM scope and keeps its API, and `FcmAccessTokenError` now extends the new `GoogleAccessTokenError`. Every source signs through WebCrypto (no new dependency), caches a token until five minutes before it expires, and shares one token request between concurrent callers. Each token request is now bounded by its timeout with its response body, also when an injected `fetch` ignores the signal, and its answer by 16 KiB; a redirect (`TOKEN_REDIRECTED`, or `TOKEN_HTTP_3xx` when not followed) and a token that is not a bearer token (`TOKEN_MALFORMED_RESPONSE`) are refused, and a request that never settles is given up after its timeout. Errors carry a code, never the private key, the signed assertion, or a token. A backend that mints its own Play tokens can switch to the source; FCM needs no change.
