npm/@mpgd/capacitor-storekit: minor (Added)
---

A durable still unfinished and bound to no `appAccountToken` (an offer code or another purchase made outside the app, then restored and granted by the backend's restore sharing) is now finished once this player's grant is journaled, instead of leaving its record `finishing` and retried on every pass. The native plugin gains an explicit no-token finish match, `finishTransaction({ transactionId, ledgerEntryId, withoutAppAccountToken: true })` with no `appAccountToken` field, which finishes only a verified, non-revoked non-consumable bound to no token; a call without a token and without the flag is still refused with `STOREKIT_FINISH_REQUIRES_GRANT`, so a missing token is never a wildcard. The new native method `getFinishSupport()` declares it (`{ withoutAppAccountToken: 1 }`); new types `StoreKitFinishSupport` and `StoreKitFinishTransactionInput`, and `CapacitorStoreKitStoreSdkPlugin` includes the optional `getFinishSupport`. The StoreKit SDK sends the no-token finish only for a listed, non-revoked `non_consumable` whose SKU the catalog declares durable, and only when the native build declares the match; with an app binary built from an earlier native plugin (`UNIMPLEMENTED`) it answers `{ finished: false }` as before, so rebuild the app to finish such records. Finishing a durable takes nothing from any player: StoreKit keeps it in `Transaction.currentEntitlements`. Consumables and subscriptions bound to no token are still never finished.
