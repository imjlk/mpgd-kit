npm/@mpgd/cli: minor (Added)

`mpgd deploy testflight distribute` takes a release's recorded iOS build beyond the internal TestFlight group: it adds the build to more internal or external groups (`--groups`, IDs or exact names), sets the build's What to Test per locale (`--what-to-test`, the `--release-notes` file format without Google Play's 500-character limit), writes the app's TestFlight review contact and notes from a `--beta-review` JSON file whose demo account names environment variables only, and submits the build for TestFlight App Review when an external group needs it. It reads App Store Connect first and writes only what differs, so a re-run never adds a group again or submits an open review again; `--dry-run` prints the plan and `--approve` is required to write. It fails before any write when a group does not exist, the build is not uploaded or still processing, an external group has no What to Test, or the review contact would be missing. The report's `betaReview.status` is `not-needed`, `not-submitted`, `waiting-for-review`, `in-review`, `approved`, `rejected` or `action-required` (export compliance, as for the internal group). `distribute` exits non-zero for `action-required` and `rejected`. `mpgd deploy testflight status` reads the same state without writing, for CI polling, and adds `build-not-ready` (poll again) and `build-unusable` (stop polling). The library exports `planTestFlightDistribution`, `applyTestFlightDistribution` and `readTestFlightBuildStatus` over a `TestFlightDistributionPort`.

The internal-group submission is unchanged except that it now reads asc 5.5.0's `testflight groups list --build-id` membership result (`{ buildId, complete, groups }`) correctly; it had expected App Store Connect group resources and reported a successful assignment as `unknown`.
