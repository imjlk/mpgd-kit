---
npm/@mpgd/platform: minor (Added)
---

New `@mpgd/platform/http-body` subpath with bounded readers for fetch-API bodies: `readBoundedJsonRequest` and `readBoundedRequestText` for a server, `readBoundedJsonResponse` and `readBoundedResponseText` for a client. Each refuses a body over `maximumBytes`, first from a declared `Content-Length` and then by counting the bytes the stream yields, so an oversized body is never buffered; stops after one `timeoutMs` for the whole read (10 seconds by default) or when an optional `signal` aborts; decodes strict UTF-8; and, for JSON, requires a JSON media type (`application/json`, `text/json` or a `+json` type) and refuses an empty body. Every refusal is an `HttpBodyError` with a stable `code` and the `status` a server answers for it (413, 408, 415 or 400); the JSON readers return `unknown`, so authentication and schema checks stay with the caller. A refusal part way through cancels the body, and so does any refusal of a response; a request refused before reading is left for the server runtime to discard. The module imports nothing and uses only web-standard globals, so the same code runs in Workers, browsers and Node, except that Firefox has no `Request.body` and the request readers reject there with a `TypeError`. Nothing existing changes; use the readers wherever an endpoint or client would otherwise call `request.json()` or `response.json()` on a body it does not trust.
