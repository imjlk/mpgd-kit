Crash reporting for the Capacitor shells. `@mpgd/platform/crash-reporting` adds the `CrashReporter` port (`recordError`, which resolves whether the report reached the service, `log`, `setCollectionEnabled`, `getStatus`), redaction and stack-frame helpers, and `installCrashErrorCapture` for WebView `error` and `unhandledrejection` events; `PlatformGateway` gains an optional `crashReporter`. `@mpgd/adapter-capacitor` implements it on Firebase Crashlytics (`@capacitor-firebase/crashlytics` 8.x, a new optional peer reached by its registered plugin name, so games do not depend on the npm package): `createCapacitorPlatformGateway` exposes `crashReporter` and, when the shell has the plugin, reports uncaught errors and unhandled rejections as non-fatal (`crashReporting: false` opts out; `crashReporting: { requireConsent: true }` holds JavaScript reports until `setCollectionEnabled(true)`). The kit adds the target, build id, app version, and adapter as custom keys; reports may also carry the game-supplied context keys, breadcrumbs (`log`), exception messages, and stack frames (function, file path, line), all sanitized and redacted first. The kit never sets a player id or Crashlytics user id. The player's stored collection choice is applied to the native SDK again at every start and retried until the SDK takes it. `mpgd target init capacitor --providers crash-reporting` installs the plugin into the shell and the Crashlytics Gradle plugin 3.0.8 into a newly generated Android project, and refuses an existing Android project without that Gradle plugin, whose app would stop at startup. The native store-policy preflight fails a production build of a shell with the plugin when its platform's Firebase config file is missing or, on Android, the Gradle plugin is not applied. Games and shells that do not request the provider are unchanged.
