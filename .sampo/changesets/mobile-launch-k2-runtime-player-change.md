npm/@mpgd/game-services: minor (Added)
---

A game services runtime now fails closed when its player is no longer the session's. New `GameServicesRuntime.dispose()` closes a runtime for good and resolves once its commerce reconciler has stopped (idempotent; a disabled runtime has nothing to close). New `sessionPlayerId` input on `createGameServicesRuntime`: it is read before every backend request and again once that request's headers are resolved, and by the commerce reconciler (new `sessionCheck` input on `createCommerceReconciler`, failure stage `session`) before each pass, queued event, record step, store read, restore, and finish, and right before a store UI opens. When it names another player the runtime closes, so one player's journaled purchases are never verified, restored, or finished with another player's credentials (which Google Play and App Store verification reject for good as an account mismatch) and no purchase is journaled under one player and bound to another store account. A closed runtime answers purchases with `failed` and the retryable diagnostic `GAME_SERVICES_PLAYER_CHANGED` (or `GAME_SERVICES_RUNTIME_DISPOSED`) before any store UI, rewarded-ad claims with `unavailable` before any ad, runs no recovery, and rejects Restore Purchases and leaderboard submissions with `GameServicesRuntimeClosedError`; while the session names no player it refuses with `GAME_SERVICES_SESSION_REQUIRED` and stays open. Refusals end no journal record, so a runtime created for that player later resumes them. `GameServicesRuntime` objects built by hand (test fakes) need a `dispose` member.
