---
npm/@mpgd/game-services: minor (Added)
---

A game services runtime now fails closed when its player is no longer the session's. New `GameServicesRuntime.dispose()` closes a runtime for good and resolves once a purchase whose store sheet is open has journaled its answer and the commerce reconciler has stopped (each wait bounded by `gameServicesDisposeWaitMs`, 3 minutes; idempotent; a disabled runtime has nothing to close). New `sessionPlayerId` input on `createGameServicesRuntime`: it is read before every backend request and again once that request's headers are resolved, and by the commerce reconciler (new `sessionCheck` input on `createCommerceReconciler`, failure stage `session`) before each pass, queued event, record step, store read, restore, and finish, and right before a store UI opens. When it names another player the runtime closes, so one player's journaled purchases are never verified, restored, or finished with another player's credentials (which Google Play and App Store verification reject for good as an account mismatch) and no store UI opens for a purchase journaled under one player once the session names another (the provider's account binding must follow the runtime's player as well, as the generated game's does, for that purchase never to be bound to the other store account). A closed runtime answers purchases with `failed` and the retryable diagnostic `GAME_SERVICES_PLAYER_CHANGED` (or `GAME_SERVICES_RUNTIME_DISPOSED`) before any store UI, rewarded-ad claims with `unavailable` before any ad (also one queued before it closed), runs no recovery, and rejects Restore Purchases and leaderboard submissions with `GameServicesRuntimeClosedError`; while the session names no player it refuses with `GAME_SERVICES_SESSION_REQUIRED` and stays open. Refusals end no journal record, so a runtime created for that player later resumes them. New `commerceAccountBinding` runtime input (reconciler `accountBinding`): this player's store account binding, derived from `playerId`; a store purchase bound to another account is left alone (reported, never journaled or verified for this player), so after a restart as another player the previous player's unacknowledged Google Play purchases are not rejected for good under this player's session and their derived keys stay free for that player's own recovery; the player's explicit Restore Purchases still takes a durable bound to another account (restore sharing). A reconciler started while the session is signed out still subscribes; its work waits for the session. `GameServicesRuntimeClosedError` now passes through header resolution and the HTTP transport unchanged instead of becoming `GameServicesHeaderResolutionError` or `GameServicesBackendTransportError`.

`GameServicesRuntime.dispose()` is now a required member. A custom or fake `GameServicesRuntime` object adds `dispose: async () => undefined` to keep compiling.

A game adopting this creates its runtime from its server session's player (never a platform placeholder), passes `sessionPlayerId` and `commerceAccountBinding`, keeps its store account binding resolver on the same player (binding nothing for anyone else), sends only the headers the runtime resolved from a custom `httpTransport`, and awaits `dispose()` before creating a runtime for another player.
