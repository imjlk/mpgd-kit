npm/@mpgd/adapter-devvit: minor (Added)

Serve notifications v2 on Devvit with the game-rendered opt-in. `@mpgd/adapter-devvit/server` adds `createDevvitNotificationsV2BridgeHandler`, which serves the `notifications.v2.*` bridge methods from `createDevvitServerNotificationProvider`: the request's logged-in user (`context.userId`, never a payload field) is opted in with `optInCurrentUser` from `requestPermission`, opted out with `optOutCurrentUser` from `revokePermission`, and read with `isOptedIn`; a logged-out viewer reads `action-required` with `requiredAction: 'login'`, a refused opt-in is `NOTIFICATIONS_CONFIGURATION_REQUIRED` (host code `DEVVIT_OPT_IN_REFUSED`), and the local-notification methods answer `NOTIFICATIONS_UNSUPPORTED`. `createDevvitPlatformGateway` gains a `notifications` option (`topics`, the ids the catalog maps for `reddit`): the gateway then exposes `notificationsV2` over the server bridge, loading its client and validators in a separate chunk on first use, adds the capability block and `providerAvailability.pushNotifications`, registers the platform user with the webview's locale and zone, and serves the v1 `notifications` adapter from the same provider. A new `loginPrompt` option (`createDevvitWebLoginPrompt()` from `@mpgd/adapter-devvit/web`, over `showLoginPrompt()`) makes `identity.requestUpgrade` open Reddit's login for a logged-out viewer and answer `reloadExpected: true`. Notifications stay a gated beta: the target config keeps `approval-required` until Reddit approves the app.
